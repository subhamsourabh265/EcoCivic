# Project documentation

- `architecture/`: system context, frontend boundaries, service ownership, and data flows.
- `adr/`: architectural decision records with context, alternatives, and consequences.
- `api/`: API contracts and lifecycle semantics.
- `security/`: OIDC flow, roles, authorization model, and threat modeling.
- `runbooks/`: development and operational procedures.
- `interview-prep/`: implementation tradeoffs and interview questions for each phase.

Record decisions as the system evolves; the root README describes the intended roadmap rather than completed capabilities.
